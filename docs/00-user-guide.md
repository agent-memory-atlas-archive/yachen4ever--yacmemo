# 用户使用手册

> 这份手册写给**使用者**：你怎么把 yacmemo 用起来、用好。设计与实现细节在 01–06 号文档，本篇只讲"怎么做"。
> 你和 yacmemo 的交互有两种方式：**通过 agent 对话**（主要方式，工具由 agent 调用），以及**直接编辑文件**（Obsidian/vim，随时可用）。两种方式操作的是同一批 markdown 文件。

---

## 一、五分钟上手

### 1. 你需要什么

- 一台常开的机器放数据和服务（下称"服务器"，例如 debsvc）；
- 局域网内可达的 embedding 端点（可选——没有它系统照常工作，只是没有语义检索和撞车检测）；
- 任何支持 MCP 的 agent（Claude Code、Codex、Cursor、Claude Desktop、自研 runtime 均可）。

### 2. 服务器上装一次

```bash
git clone <your-repo> /srv/yacmemo && cd /srv/yacmemo
uv sync
cp config.example.toml config.toml
```

编辑 `config.toml`，三件事：

```toml
[embedding]                          # 你的 embedding 服务
base_url = "http://m2ultra:11235/v1"
api_key = "sk-..."
model = "Qwen3-Embedding-0.6B-4bit-DWQ"   # 必须和 /v1/models 返回的 ID 一字不差

[server]
host = "0.0.0.0"
port = 9721

[[users]]                            # 每个人一条；id 用作 URL 路径
id = "yachen"
root = "/srv/yacmemo/yachen/memory"
```

启动并验证：

```bash
uv run yacmemo-server --config config.toml
curl http://127.0.0.1:9721/health     # → {"status":"ok","users":[...]}
```

长期使用建议配 systemd（见 [05-deployment.md](05-deployment.md) 第 1.3 节）。

### 3. 每台电脑上接一次

在你的 agent 里添加远程 MCP（以 Claude Code 为例）：

```bash
claude mcp add --transport http yacmemo http://debsvc.local:9721/yachen/mcp
```

Cursor / Claude Desktop 在 mcp.json 里加 `"yacmemo": {"url": "..."}`；自研 runtime 用任意 MCP 客户端库连这个 URL。换路径 = 换用户（`/user2/mcp`）。

### 4. 贴约定块

把 [01-architecture.md](01-architecture.md) 第八节那段"记忆使用约定"贴进 agent 的系统提示/CLAUDE.md/AGENTS.md。这决定了 agent 写记忆的质量——不贴也能用（有守卫兜底），贴了体验好得多。

### 5. 验证一下

对 agent 说：

> "帮我记一下：我家服务器 debsvc 的 IP 是 192.168.5.7"

然后新开一个 session 问：

> "我家服务器的 IP 是多少？"

能答出 192.168.5.7，说明整条链路通了。

## 二、日常怎么用

### 2.1 记什么：结论，不是过程

记忆的价值在于"下次不用重新解释"。值得记的：

- **事实与配置**："yacmemo 服务端口是 9721"、"NAS 的备份共享路径是 /volume1/backup"；
- **决策与原因**："选 restic 而不是 timeshift，因为要跨机备份"；
- **偏好**："commit message 用中文"、"部署前先跑测试"。

不值得记的：对话过程、临时调试输出、一次性的中间状态。**agent 已经把结论提炼好了，你只需要让它记。**

### 2.2 怎么记：对 agent 说话就行

```
"把这个记到记忆里：yacmemo 的服务端口改成了 8080，原因是……"
```

agent 会：先查有没有同主题笔记 → 有就 `memory_edit` 更新 → 没有就 `memory_write` 新建。你不需要指定文件名和路径，但知道这些约定能配合得更好：

- **标题 = 主题名**（如"yacmemo部署配置"），不要带日期和"-2"这种尾巴——守卫会拒绝近似重复的标题，这是防重复记忆的机制，不是故障；
- **一件事一篇笔记**：端口配置和备份策略是两篇，不要混在一篇里；
- **先有主题才能写**：写入被限定在已注册主题的目录内（主题注册制硬约束，agent 绕不过）——想让 agent 长期记一件新事，先说"把 X 加入长期记忆"（见 2.5）；流水账类放 `journal/`（免注册区，按日期命名，不做合并）。

### 2.3 怎么查

```
"我的记忆里，yacmemo 的端口配置在哪？"
"之前是怎么解决 LanceDB 删除报错的？"
```

检索是 FTS + 语义双路融合。实测经验（见 [06-evaluation.md](06-evaluation.md)）：

- **关键词式问法命中率高**："yacmemo 端口"、"restic 备份"；
- **两字短词也能搜到**（"端口"自动走子串回退）；若向量通道故障会看到降级提示，此时换 ≥3 字关键词更稳；
- 自然语句（"端口是多少来着"）靠语义通道也能命中大半；
- 找到后 agent 会顺着"相关笔记"链接读上下文——不用你自己拼线索。

### 2.4 怎么改

事实变了直接说：

> "yacmemo 端口改成 9721 了，更新一下记忆。"

agent 用 `memory_edit` 就地修改（旧的值被替换，不会留下两条矛盾记录）。整个小节重写用 `memory_edit_section`。**如果发现记忆里有两条互相矛盾的旧记录**（历史遗留），直接说"这两条矛盾，合并一下"，agent 会按 ⚠ 标注处理。

### 2.5 主题注册：主次之分

长期记忆按**主题**组织，主题由你显式声明。想长期记录一件事时对 agent 说：

> "把 notecalc 这个项目加入长期记忆"

agent 会调 `topic_register` 注册：登记进 TOPICS.md 注册表 + 创建 `topics/<主题>/abstract.md`（主题目录）。之后该主题的详细笔记都写入主题目录（agent 可按模块增设），现状变化**就地更新 abstract**。**注册同时是写入的授权**：主题目录之外的写入会被硬拦截，所以"先注册、后写入"是让 agent 长期记住一件新事的唯一路径。拦截消息自带**近失诊断**——agent 写错路径（如漏了 `topics/` 前缀）时，错误会直接给出修正后的写入路径，一轮自纠不用猜。

- `topic_list` / WebUI 健康页可随时查看有哪些主题（活跃/已归档分组）；
- **项目翻篇了**："notecalc-iced 归档吧"——agent 调 `archive_topic`：整个主题目录移入 `archive/`，**检索仍可用**，只是会话回顾不再注入；想彻底移除才用注销（笔记变游离文件，走审计裁决）；
- 审计页会点名"游离文件"（不属于任何主题的散笔记）——让 agent 归位或删除；
- 审计还会点名"缺向量笔记"并自动重试补齐——embedding 端点故障期间写入的笔记不会永远丢语义检索；
- 会话开始时 agent 会先调 `memory_context` 回顾你的画像/偏好与全部活跃主题——新 session 不再从零开始。

### 2.5.1 画像与偏好：记忆层的功能，不占主题

你的画像与协作偏好（身份、沟通风格、材料格式等）存在根目录 `PROFILE.md`，**它不是主题**——是记忆层的功能文件。对 agent 说：

> "记住：我的报告都要公文体。"

agent 调 `update_user_preference` 按小节维护（如"材料与文档偏好"）。每次会话开始，`memory_context` 会把画像**前置注入**——任何 agent 第一步就"认识你"，不用翻主题。

### 2.6 curator 每周提案

每周六凌晨 curator（可配置的 LLM 审查员）会自动做一次全库质量审查，产出《提案报告》。**它只提案、绝不执行**——你在报告里挑认可的条目，让 agent 执行即可。随时手动触发：WebUI 审计页 →「深度审查」按钮（约 1-2 分钟）；历史提案在审计页「质量提案」区按日期查看。curator 用哪个 LLM、加哪些用户，都在 WebUI「设置」页的 config.toml 里改（保存自动校验+备份，改完重启生效）。当然，你也可以随时直接指挥（就像本手册通篇的做法）。

### 2.7 审计习惯

```
"帮我做一次记忆审计。"
```

agent 调 `memory_audit`，输出六类信息：

| 输出 | 含义 | 你要做什么 |
|---|---|---|
| 外部修改（已重建索引） | 你在 Obsidian/vim 直接改过的文件，索引已自动对齐 | 无 |
| 外部删除（已清理索引） | 你直接删掉的文件，索引已清理 | 无 |
| 标题重复 / 语义撞车 | 疑似同一主题有两篇 | 决定保留哪篇，让 agent 合并 |
| 悬空链接 | `[[链接]]` 指向不存在的笔记 | 让 agent 创建目标或删掉链接 |
| 悬空主题卡 | 注册表里指向的 abstract 文件不存在（多为手工编辑注册表/目录重组的遗留） | 让 agent 修正注册表路径或重建卡 |
| 游离文件 | 存在但不属于任何注册主题的散文件 | 决定注册成主题、归位到某主题目录，或删除 |

建议每周一次，或感觉"记忆有点乱"的时候随时做。

> WebUI 审计页更顺手：审计快照**每日一份**（`journal/audit/<日期>.md`，同日重跑以"复审"小节追加），对每条问题（标题重复/撞车/悬空/游离）可直接点「已处理」或「忽略」，处置记录随快照留存、已处理的不会反复提醒；过期快照由 curator 每周自动清理（默认保留 7 天）——详见 [07-webui.md](07-webui.md) §2.3。

## 三、直接编辑文件（不用 agent）

memory 目录就是普通 markdown，你可以完全绕开 agent：

- **Obsidian**：把 memory 目录作为 vault 打开，wiki-link 图谱直接可用；
- **vim/任意编辑器**：随便改。

系统会自愈：

- 你改了文件 → 下次 `memory_audit`（你或 agent 发起）时索引自动重建，内容 hash 变化的部分重新向量化；
- 你删了文件 → audit 清理索引并报告；
- 你新建的文件 → audit 重算时纳入索引。

这些外部改动在 audit 时同时被 git 收编为一条 `external:` 快照——索引与历史保持一致。

三条纪律：

1. **别动 `.index/` 目录**——那是派生索引，动了也没事，删掉能重建，但没必要碰；
2. **新建文件请用"# 标题"开头**，标题会作为检索与合并的标识；
3. **别复制粘贴制造近似标题**（"XX"和"XX-2"）——audit 会把它们标为重复，又得人工合并。

## 四、多人使用

每个人一条 `[[users]]`，同一台服务器、同一个端口：

```toml
[[users]]
id = "user2"
root = "/srv/yacmemo/user2/memory"
```

- 用户2的设备上 agent 添加 `http://debsvc.local:9721/user2/mcp`；
- **隔离是物理的**（不同目录），不是字段过滤——两人可以有同名笔记互不影响，谁也搜不到对方的记忆；
- 各自的系统提示里贴同一份约定块即可。

## 五、备份与迁移

- **备份 = 备份两个 memory 目录**。`.index/` 不用备（可重建）；真正不可再生的只有 markdown 和 git 历史；
- git 历史是自动的：每次写入/编辑/删除/主题操作都会自动 commit（无需人工维护，仓库永远干净），误删可从历史找回；
- **迁移**：新机器拷贝 memory 目录 → 改 config 里的 root 路径 → 启动。索引会自动重建。

## 六、WebUI 控制台

浏览器打开 `http://debsvc.local:9721/ui/`（服务端自带，无需安装任何东西）：

- **笔记**：左侧列表按用户浏览，正文用 markdown 渲染；"编辑"直接改源文件并同步索引；"＋"新建（近似标题守卫在这里同样生效，被拒时勾选"强制(force)"再保存即可——网页上点按钮的就是人工确认）；"删除"同时清理索引（git 里仍可找回）；
- **搜索**：随时手动验证检索效果，支持 hybrid/fts/vector 三通道切换，⚠ 标注直接可见，点结果跳转到笔记；
- **审计**：双模式——「确定性审计」快速自愈 + 规则检测（标题重复/语义撞车/悬空链接/游离文件），「深度审查」由配置的 LLM 产出提案报告；撞车条目带"已合并 / 忽略"按钮，这就是人工裁决的入口；
- **使用记录**：每次 MCP 工具调用**与 WebUI 控制台变更**（保存/新建/删除/画像编辑，client 标记为 `webui`）的留痕（时间、用户、工具、内容摘要、客户端 UA、IP、耗时、变更前内容 hash）——试用期最重要的观察页：哪些客户端在用、调了什么、写入了什么、有没有报错；
- **健康**：embedding 配置状态、各用户笔记数/撞车数/守卫统计、**主题记忆一览表**、curator 提案计数、客户端清单、近 14 天调用量与错误数；
- **设置**：config.toml 在线编辑（用户 / embedding 模型 / curator LLM）——保存前自动校验并备份，可选重启服务。

页面功能与 API 的完整说明见 [07-webui.md](07-webui.md)。

**试用期的建议姿势**：笔记页随手看 agent 写了什么；搜索页验证召回质量；审计页每周点一次；使用记录页观察两周的调用构成——这些就是 P4 要回收的原始数据。

## 七、常见问题

**Q：agent 写笔记被拒绝了，说"已存在近似标题笔记"？**
这不是故障，是防重复机制在起作用。它说明记忆里已经有同主题笔记——让 agent "更新它"而不是新建。确信是不同主题时，agent 可以用 `force=true` 越过（24 小时内 force 超过 3 次会要求二次确认，都是可数的审计指标）。

**Q：搜索结果里的 ⚠ 是什么意思？**
"这篇笔记和另一篇疑似在说同一件事"。让 agent 读两篇合并即可。系统永远不会自己删——宁可让你多看一眼，不让正确的记忆消失。

**Q：审计里的"语义撞车"该怎么处理？**
见上方 WebUI 一节的三种情况：同一主题的两份拷贝 → 合并成一篇后点「已处理」；不同主题恰好同一条事实 → 点「忽略」。撞车按笔记对分组，每组可直接点「打开 A / 打开 B」跳去核对。

**Q：搜不到我确定记过的东西？**
按顺序排查：① 换关键词式问法（"端口 9721" 而不是 "端口是多少"）；② `memory_list` 看文件在不在；③ `memory_audit` 看是否外部修改未对齐；④ `/health` 和 config 检查 embedding 端点——断了的会话义检索（自然语句问法）失效，检索结果会带"向量通道不可用"降级提示，关键词检索（含两字短词的子串回退）仍可用；

**Q：embedding 服务挂了会怎样？**
写入照常、关键词检索照常；自然语句检索和撞车检测暂停，恢复后自动补齐（下次写入或 audit）。不需要人工干预。

**Q：索引是不是坏了/能删吗？**
能。`.index/` 全部是派生数据，删掉后重启服务（或让 agent 做一次 audit/reindex）即从 markdown 全量重建。记忆本体毫发无损。

**Q：换 agent（比如从 Claude Code 换成别的）记忆会丢吗？**
不会。记忆在服务器上的 markdown 文件里，任何 agent 都是通过同一个 URL 访问同一份数据。这正是本项目的出发点。

**Q：两台电脑同时让 agent 写记忆会冲突吗？**
并发请求在服务端被串行化（加锁），SQLite/LanceDB 不会写坏；两台同时写同一篇笔记时后写的生效（和所有编辑器一样）。正常使用碰不到竞态问题。

**Q：我想重置一切从头开始？**
删掉两个 memory 目录（或 git 里开新分支）→ 重启服务。索引与记忆一起归零。`.index/` 单独删则是只重置索引。

**Q：怎么删除某条记忆？**
对 agent 说"删掉 X"，它会调 `memory_delete`（仅在你明确要求时才会执行）；WebUI 笔记页也有删除按钮。删除会自动产生 git 快照，随时可从历史找回。

## 八、好习惯清单

- [ ] 系统提示里贴了约定块
- [ ] 每周做一次 `memory_audit`（或 WebUI 审计页点一下），顺带确认 `== git ==` 行显示"启用"（快照机制健康）
- [ ] memory 目录有异地备份（本地 git 快照只防误删，不防磁盘损坏）
- [ ] 让 agent 大量记录前，先用几条真实事项试一周，看看它的命名和合并习惯
- [ ] `journal/` 只放流水账，别把该立主题的笔记埋进去
- [ ] 记忆超过几百篇后，重跑一次 [评测脚本](06-evaluation.md)，看看真实数据下的命中率
